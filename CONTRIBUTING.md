# Contributing

This repo is a **grounded catalog**, not a speculation board. Every problem entry
must trace to a real incident, research paper, or production report.

## Adding a new problem

1. Open `PROBLEMS.md`.
2. Add an entry under the most fitting cluster (or a new cluster if needed).
3. Use the standard shape: Problem → Real incident → Why current solutions fall
   short → What a good solution needs → Study → References.
4. Add the source to `REFERENCES.md` with a numbered link.
5. Add a row to the index table in `README.md`.

## Adding a project that *closes* a gap

If you know of an open-source project that genuinely addresses one of the 13
problems, add it to the relevant "Study" list in `PROBLEMS.md` and, if notable,
to the reference table in `REFERENCES.md`. Prefer projects with a live repo and a
clear relationship to the problem.

## Rules

- No unsourced claims. If it's an opinion, label it as one.
- Keep star counts dated (they rot fast).
- Be precise about what is *solved* vs *partial* vs *open* — that distinction is
  the whole point of the repo.
